# AI PDF Question Answering Chatbot

Upload PDF documents, ask questions in plain English, and get answers that cite the file name and page number they came from. Answers are generated by Google Gemini (free tier), but only from your documents.

This project uses **Retrieval-Augmented Generation (RAG)**: the app finds the most relevant parts of your PDFs and gives only those parts to Gemini.

## 1. Features

- **PDF upload**: drag and drop, file picker or sidebar button. Several files at once. PDF only, up to 20 MB each.
- **Smart checks**: rejects non-PDF files, detects duplicates (the same file is never indexed twice), and explains problems with password-protected, damaged or scanned PDFs.
- **Processing status**: every document shows Ready, Processing, OCR needed, Failed and so on.
- **Semantic search**: finds relevant text by meaning, not only exact words.
- **Answers with citations**: each answer lists sources such as `[S1] manual.pdf · page 3`.
- **Clickable citations**: opens the PDF at the cited page, with previous/next page and zoom controls.
- **Multiple documents**: ask across all documents, or tick the ones you want to use.
- **Document-only answers**: if the PDFs do not contain the answer, the app says so and does not call Gemini. Irrelevant questions do not produce made-up answers.
- **Follow-up questions**: earlier messages in the conversation are used as context.
- **Summaries**: an overview of a document, and chapter-by-chapter summaries when headings can be found.
- **Chat history**: conversations are saved; you can open, rename or delete them.
- **Copy and feedback**: copy any answer, and mark answers as helpful or not helpful (saved).
- **Suggested questions**, loading indicators, empty states and friendly error messages.
- **Responsive layout**: works on desktop, tablet and phone.

## 4. Complete RAG workflow

**Document ingestion (upload):**

```
PDF upload → text extraction (PyMuPDF) → text cleaning → chunking (1000 characters, 150 overlap)
  → embeddings (all-MiniLM-L6-v2) → ChromaDB storage → SQLite metadata storage
```

**Question answering:**

```
User question → validation → question embedding → semantic search (top 5, optionally filtered by document)
  → similarity threshold (default 0.25) → context preparation (labelled excerpts S1…S5)
  → Gemini API (strict rules + excerpts + recent messages + question)
  → answer validation (JSON checked with Pydantic) → citation formatting → response
```

Key settings: chunk size and overlap, top-k, similarity threshold, Gemini model and output token limit are all in `backend/.env`. Why these values were chosen is explained in [docs/architecture.md](docs/architecture.md).

## 6. Database architecture

Two stores, each with one job:

- **SQLite** (`documents`, `document_chunks`, `conversations`, `messages`): application data with foreign keys and cascading deletes.
- **ChromaDB**: embedding vectors plus the chunk text used for search. Each chunk row in SQLite stores the matching `vector_id`, so vectors are not duplicated in SQLite.

Full table descriptions, constraints and a diagram: [docs/database_design.md](docs/database_design.md).

## 13. Using the chatbot

2. **Check status**: each document shows its status. Wait for **Ready**.

## 14. Common errors and solutions

| Message you see | What it means | What to do |
| --- | --- | --- |
| Backend offline | The API server is not running. | Start the backend (section 11). |
| Gemini key not set / key is not configured | `GEMINI_API_KEY` is empty. | Section 9. |
| Gemini rejected the API key | The key is wrong or disabled. | Check `backend/.env`. |
| The Gemini model … was not found | `GEMINI_MODEL` is not available. | Check AI Studio and set a current model. |
| Gemini free-tier rate limit or daily quota reached | Too many requests, or the free daily quota is used up. | Wait a minute, or try again after the quota resets. Check AI Studio. |
| This PDF looks scanned … OCR is required | There is no text layer to read. | See "Scanned PDFs" below. |
| This PDF is password protected | The file is encrypted. | Save a copy without the password, then upload it. |
| This PDF is damaged / could not be read | The file is corrupt or not a standard PDF. | Try opening it in a PDF reader and saving a fresh copy. |
| The file is larger than 20 MB | Over the upload limit. | Split the PDF, or raise `MAX_UPLOAD_SIZE_MB`. |
| I could not find an answer … | No text in your PDFs matched the question closely enough. | Rephrase, select the right document, or upload the PDF. |
| Cannot reach the server | The browser cannot reach the backend. | Start the backend, and keep both windows open. |
| Port already in use | Another program uses port 8000 or 5173. | Stop it, or use another port. |

**Scanned PDFs:** this version does not run OCR (optical character recognition). Options: (a) run OCR in a PDF tool such as Adobe Acrobat or `ocrmypdf` and upload the result; (b) add an OCR step to `pdf_service.py` (for example with `pytesseract`, which needs the Tesseract program installed).

**Slow first answer:** the embedding model is loaded on first use. Later questions are faster.

## 16. Deployment guidance

The app is built for **one user on one computer**. Before putting it on the internet, you must add:

- **Authentication and per-user data**: anyone who can reach the server can read and delete documents and chats.
- **HTTPS**: put the app behind a reverse proxy such as Caddy or Nginx with a certificate.
- **Background processing** for large PDFs: indexing currently runs inside the upload request.
- **Backups** of `storage/` and the SQLite database.
- **Rate limiting** on the upload and chat endpoints, to control API usage.
- **Monitoring and log retention** and a real database (PostgreSQL) if many users will share the app.

Do not deploy publicly with the default settings, and do not publish your API key.

## 17. Security limitations

Current protections:

- The API key stays on the server and is not logged.
- Only PDF files are accepted (the file signature is checked, not just the extension). Size is limited.
- Stored files use random names; paths are checked against the storage folder.
- Deleted files are overwritten before removal.
- Gemini is instructed to treat document text as untrusted and to ignore instructions inside it. Excerpt tags cannot be closed early by document text.
- Answers are limited to retrieved document text, with a relevance threshold.
- Internal error details are not shown to users.

Known limitations (not solved in this version):

- **No login or accounts.** Anyone with access to the server can use it.
- **Prompt injection is reduced, not eliminated.** A cleverly written PDF can still influence an answer. Treat answers as helpful, not authoritative.
- **Overwriting does not guarantee erasure** on SSDs or journaled file systems. Use full-disk encryption for sensitive data.
- **Uploaded PDF excerpts are sent to Google Gemini** when you ask questions. Google's free-tier terms let Google use free-tier requests to improve its products. Do not use confidential documents unless you accept those terms.
- **No rate limiting** of our own endpoints.
- **Single process only.** SQLite and ChromaDB are used by one server process at a time.
- **Summaries of very long documents** use evenly spaced sections, not every page.

## PDF extraction (Phase 7)

- **Tables:** ruled tables are found with pdfplumber. Each table is indexed as text (for example `XR-500 | 750 W`) with its page number, so questions about table values cite the right page. Table search stops after `TABLE_TIME_BUDGET_SECONDS` (default 120) on very large PDFs, and the text is still indexed. Tables without ruling lines are not detected.
- **Blank and scanned pages:** pages without text are counted and shown on the document card. OCR is detected but not run: the health check reports whether Tesseract is installed, and a scanned PDF is refused with a clear message. Nothing is installed automatically.
- **Large PDFs:** up to 1000 pages (`MAX_PDF_PAGES`). Embeddings are computed in batches of 256. Larger files are refused before indexing.
- **Errors:** a damaged page or a failed table search is skipped, and the rest of the PDF is indexed. A PDF where every page fails is marked corrupt.
- **New package:** `pdfplumber` (table extraction), listed in `backend/requirements.txt`.

## Gemini quota and error messages

- When the Gemini free-tier quota or rate limit is reached, the app says so in plain English, for example "The Gemini free-tier quota is used up for now, so no request was sent to Gemini."
- After a quota error, the app stops sending new Gemini requests for 5 minutes (`GEMINI_QUOTA_COOLDOWN_SECONDS`, default 300). It does not retry each click.
- Other Gemini problems (outages, timeouts, key problems) keep their own messages and the existing retry rules.
- Internal server errors are no longer shown for Gemini or study problems; those return the real message and status.

## Reliability, streaming and data safety (Phase 0 and Phase 1)

**Database migrations (Alembic).** Schema changes are applied with Alembic when the server starts. Before a migration runs, the database is copied to `backend/data/backups/auto-before-migration-*.db`. The baseline migration only creates tables that are missing, so your existing tables and rows are never dropped or changed. To check the current version:

```powershell
cd backend
.\.venv\Scriptslembic.exe current
```

Manual backups are kept in `backend/data/backups/` and in the copies of `storage/` made before this change. Keep them until you are satisfied with the new version.

**Streaming answers.** `POST /api/chat/stream` sends the answer as it is written (Server-Sent Events: `meta`, `delta`, `done`, `error`). Problems before the first word are shown as normal errors (for example 503 or 504). Problems during the answer are sent as an `error` event, and nothing is saved, so the question can be asked again.

**Cooldown.** After 3 outage-type failures in a row (503, 504, timeouts, connection errors), Gemini calls fail fast for 60 seconds with a message that says when to try again. Cached answers still work. Rate-limit and bad-key errors do not trigger the cooldown.

**No duplicates.** Identical concurrent Gemini calls share one request. Chat questions sent with the same `client_request_id` are saved once. Study generation requests that repeat within 2 minutes return the first result.

**Answer cache.** Identical prompts reuse the answer for 15 minutes. The cache key includes the PDF excerpts, the model and the generation options, so a different PDF selection or option never reuses an answer.

**Privacy.** API keys are removed from log lines. Prompts, PDF text and answers are never logged.

## Chat interface (Phase 2)

# PDF Question Answering Chatbot

An AI-powered application that allows users to upload PDF documents, ask questions, and get answers with source citations.

## Features

- Upload and read PDF documents.
- Ask questions about uploaded PDFs.
- Get answers using AI.
- Search relevant information using semantic search.
- Generate short and detailed study notes.
- Generate quizzes and check scores.
- Create flashcards.
- Explain topics in simple language.

## Technologies Used

- Frontend: React, Vite, Tailwind CSS
- Backend: Python, FastAPI
- AI: Google Gemini
- RAG: LangChain, Sentence Transformers
- Vector Database: ChromaDB
- Database: SQLite
- PDF Processing: PyMuPDF

## Workflow

1. Upload a PDF.
2. Extract and split PDF text into chunks.
3. Generate embeddings and store them in ChromaDB.
4. Retrieve relevant content based on user questions.
5. Generate AI answers with source citations.
